## 1. Roslyn: what it is and where it is

1. Roslyn is the .NET Compiler Platform: Microsoft's open-source C# and Visual Basic compilers, with APIs for analysing and compiling code.
2. Source: https://github.com/dotnet/roslyn, under the MIT licence, part of the .NET Foundation.
3. Official packages: `Microsoft.CodeAnalysis.*` on NuGet. Each NuGet page links to the dotnet/roslyn commit the package was built from.
4. Two ways to compile at run time:
   1. `CSharpCompilation` (package `Microsoft.CodeAnalysis.CSharp`) compiles source text into an assembly in memory, which is then loaded and called.
   2. `CSharpScript` (package `Microsoft.CodeAnalysis.CSharp.Scripting`) evaluates C# snippets directly.
5. Roslyn turns C# into IL. The JIT in the .NET runtime (`dotnet/runtime`) then turns IL into machine code.
6. "Roslyn C# – Runtime Compiler" on the Unity Asset Store is a separate, commercial package that bundles the open-source Roslyn. The owner has used it, and it worked. The plan below is a fresh start that does not use it.

## 3. C# in the neural-net applications and editors

11. **C# as a third language in the editor:** the Language choice offers Wolfram, Python and C#, and the editor generates a `.cs` file for a drawn net.
12. **Our own nets in C#:** a C# library that matches `ccn_nets.nn` (dense layers, softmax, backpropagation, Adam, gradient check, save/load), checked against the Wolfram and Python reference results.
13. **Roslyn host:** a small program that compiles and runs the generated C# at run time.
14. Limits:
    1. Roslyn cannot run inside the editor page without a heavy WebAssembly .NET runtime. The editor generates the code, and Roslyn runs it on the machine.
    2. Wolfram's .NET/Link is, as far as known, Windows-only. On a Mac, Wolfram and C# would share data through files.
    3. The sequence (transformer) elements come after the small nets, as they did for Python.

## 4. Unity 6.4 and later

15. **Editor:** run-time compiling works, because the Editor uses Mono's JIT.
16. **Mono player builds** (desktop and Android): run-time compiling works.
17. **IL2CPP player builds** (iOS, WebGL, most consoles): IL2CPP compiles ahead of time, so code compiled while the game runs cannot be executed. The only way round it is an interpreter for the compiled code, which is slower and harder to set up.
18. **Unity's roadmap:**
    1. Unity 6.7 LTS will be the last release built on Mono.
    2. Unity 6.8 is planned to bring a CoreCLR Editor, a non-experimental CoreCLR desktop player, and an IL2CPP player with .NET and C# 14.
    3. CoreCLR compiles just in time, so run-time compiling should keep working on desktop. Mobile, WebGL and console builds keep the IL2CPP limit.
19. **Suggestion for our nets:** a net is a structure plus its weights, and both are data. The C# net library is built into the project, and the editor exports each net as a data file that the game loads. This works with every back end, IL2CPP included. Run-time compiling stays an extra for desktop and the Editor.

## 5. The fresh start: our own Unity run-time compiler

20. **The compiler:** the official Roslyn DLLs in their .NET Standard 2.0 builds, with their dependencies, in `Assets/Plugins`.
21. **Our own compile service:**
    1. compiles source text in memory;
    2. finds references by itself, from the Editor's assemblies or the build's `Managed` folder;
    3. loads the result into the running game;
    4. returns errors with line numbers, ready to show on screen.
22. **Security check:** before compiling, a Roslyn syntax check refuses namespaces and types that are not allowed (for example `System.IO`, `System.Net`, reflection).
23. **Hooks into Unity:**
    1. a component that compiles a script and attaches it to a GameObject;
    2. an in-game console for typing and running C#;
    3. reloading a script after it is edited.
24. **Link to our nets:** C# generated by the editor is compiled inside Unity, and the same nets load as data in IL2CPP builds.
25. **Testing:**
    1. Ubuntu packages Mono, so the compile service can probably be tested under Mono and .NET in Claude's workspace.
    2. The Unity parts are tested in the owner's project.
